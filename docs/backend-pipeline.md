# 后端与构建数据流

本站主要在构建期处理内容，线上 Node 服务只提供静态文件和 `/healthz`。

Vault 同步流程：扫描文件 → 归一化笔记并筛选公开内容 → 生成内存计划 → 编译有效配置 → 增量写入生成物。

| 模块 | 职责 |
| --- | --- |
| `tools/vault/core.mjs` | 内容归一化、发布窗口、领域分组和输出计划；`compileVault` 保持现有调用方式 |
| `tools/vault/files.mjs` | 文件清单、目录边界和按最终字节比较写入 |
| `tools/vault/resources.mjs` | 附件路径索引、资源 URL、单次构建内哈希复用及按目标去重 |
| `tools/vault/outputs.mjs` | 生成物格式化、增量写入和过期文件清理 |
| `tools/vault/sync.mjs` | 编排配置与站点资源同步，内容变化时刷新 Astro 内容缓存 |

单次编译共用文件清单，附件优先匹配笔记相对路径，再匹配完整路径，最后使用无歧义的路径后缀。附件内容哈希用于稳定公开 URL 和去重；没有额外的格式哈希清单。

生成物先在内存中格式化，再与现有文件比较；相同内容保留修改时间。撤稿、删除和改名仍会清理原生成物及独占附件。原 Vault 始终作为只读输入。

配置预检与正式写入使用同一份生成后的配置，包括 Vault 公告。配置类型失败时恢复上次的配置模块。站点资产在笔记和配置通过处理后同步。

`src/utils/content-utils.ts` 集中处理文章与动态的草稿策略，文章导航使用独立数据副本。分类与标签以索引查询名称和顺序；统计动态数量时不初始化 Markdown 渲染器。

`scripts/deploy/server.mjs` 在创建服务时准备静态配置和健康状态，所有请求复用。公开接口、缓存规则和媒体 Range 行为保持兼容。

发布流程只在 `build` 中检查一次静态产物，不在打包时重复扫描；本机不回验刚生成的压缩包哈希。部署仍生成现有服务器需要的校验文件，版本新鲜度只在服务器激活前检查一次。
